# AdCompass — 마케팅 성과 대시보드

광고 성과를 읽고 **「다음에 무엇을 할지」까지 제안하는** 대시보드.

청년 K-뉴딜 아카데미 Adobe AI 콘텐츠 마케팅 과정 — AGM 1기 · 대전 한남대학교 캡스톤.
**배포: https://giftly-sable-mu.vercel.app/**

---

## 이 프로젝트가 답하려는 질문

> 광고를 돌렸는데, **다음엔 어디에 더 쓰면 되지?**

광고 관리자는 숫자를 잘 보여줍니다. 그런데 마케터가 실제로 막히는 건
"CPA가 13,700원이구나"가 아니라 **"그래서 카카오 예산을 어떻게 할까"**입니다.
그 판단은 지금도 대부분 감으로 이루어지고, 팀장에게 설명할 근거가 없습니다.

이 대시보드는 제안마다 **근거 · 실행 방법 · 기대 효과와 그 계산식, 그리고 가정**을
함께 띄웁니다.

## 화면 구성

```
/                 대시보드 (본체)
/demo             샘플 광고 랜딩  ← A/B 자동 분기
  /product          상품 상세
  /cart             장바구니
  /done             구매 완료
/admin            수집 원본 조회 (Supabase 연결 시)
```

**랜딩을 함께 만든 이유:** 대시보드만 있으면 데이터가 어디서 오는지 설명할 수
없습니다. 측정 대상과 측정 도구를 둘 다 만들어야 이벤트 설계가 실제로 맞는지
검증됩니다. `/demo`의 4단계는 대시보드 퍼널 차트의 4단계와 정확히 같습니다.

## 5분 안에 실행하기

```bash
npm install
npm run dev        # http://localhost:3000
```

**환경변수 없이도 전부 동작합니다.** 대시보드는 샘플 데이터로 채워지고,
랜딩은 수집만 건너뜁니다.

A/B를 강제로 바꾸려면 브라우저 콘솔에서:

```js
localStorage.setItem('smp_variant', 'B'); location.reload();
```

## ⚠️ 샘플 데이터

**대시보드의 모든 수치는 가상입니다.** 광고를 집행하지 못했기 때문이고,
화면 상단에 「샘플 데이터」 배지가 상시 노출됩니다.

- `src/data/mock/generate.ts` — 업종 5종 × 채널 5개 × 28일
- **시드 고정 난수**를 씁니다. 새로고침해도 값이 변하지 않습니다 —
  발표 중에 숫자가 바뀌면 고장난 것처럼 보이기 때문입니다.
- 업종마다 채널 성향·소재 피로도·퍼널 병목·A/B 효과가 다르게 설정돼 있어
  **업종을 바꾸면 제안도 실제로 달라집니다.**

| 업종 | 최우선 제안 | A/B |
|---|---|---|
| 패션 · 의류 | 카카오 → 유튜브 | 유의 |
| 식품 · F&B | 유튜브 → 네이버 | **미판정** |
| 뷰티 · 화장품 | 소재 교체 | 유의 |
| 교육 · 클래스 | 메타 → 구글 | **미판정** |
| 리빙 · 인테리어 | 카카오 → 네이버 | 유의 |

식품·교육이 「미판정」으로 나오는 것이 **의도**입니다. 차이가 작으면 유의하지 않다고
정직하게 말합니다.

### 실계정 연결

`INDUSTRIES` 대신 광고 API 응답을 `src/data/mock/types.ts` 형태로 매핑해 넣으면
**화면은 그대로 씁니다.** 데이터 소스만 갈아끼우는 구조입니다.

## 제안 엔진 — `src/lib/insights.ts`

| 규칙 | 트리거 |
|---|---|
| 예산 재배분 | 채널 간 ROAS 격차 60%p 초과 |
| 소재 교체 | 초반 대비 후반 CTR 18% 이상 하락 |
| 타겟 집중 | 세그먼트 CVR이 전체 평균의 1.3배 초과 |
| 랜딩 개선 | 퍼널 최대 이탈 구간 |
| 실험 판정 | 2×2 카이제곱 p < 0.05 |

**LLM을 호출하지 않습니다.** 판단 근거를 화면에 그대로 보여줄 수 있어야 하기
때문입니다. "AI가 그렇게 말했다"는 마케터가 사장님께 할 수 있는 설명이 아닙니다.

**우선순위는 절대 임계값이 아니라 상대 순위로 매깁니다.** 임계값으로 만들었더니
다섯 개가 전부 「높음」으로 나왔습니다. 다 급하면 아무것도 안 급합니다.

## 차트 — `src/components/charts.tsx`

외부 라이브러리 없이 인라인 SVG와 div로 그립니다. 색은 검증기를 통과한 값만 씁니다.

| 용도 | 색 | 검증 |
|---|---|---|
| 단일 계열 · 순차 | `#2a78d6` | — |
| 퍼널 5단계 순서형 | `#86b6ef` → `#104281` | 단일 색조 · 명도 단조 증가 |
| A/B 2계열 | `#2a78d6` · `#008300` | 색각이상 ΔE 26.5 / 일반시야 ΔE 29.0 |

**이중 축은 쓰지 않습니다.** 척도가 다른 두 지표는 차트를 나눕니다.

## 이벤트 설계

`/demo` 흐름에서 4종이 발생합니다.

```
page_view  →  view_product  →  add_to_cart  →  purchase
랜딩 진입      상품 조회        장바구니        구매 완료
```

모든 이벤트에 `variant`와 `session_id`가 붙습니다. 하나라도 없으면 그 이벤트는
A/B 분석에서 통째로 빠지므로 **아예 발송하지 않습니다** (`src/lib/analytics.ts`).

### GA4 연결

`.env.local`에 `NEXT_PUBLIC_GA_ID=G-XXXXXXX`를 넣습니다.

**⚠️ 그다음이 더 중요합니다.** `관리 > 데이터 표시 > 맞춤 정의`에서 아래를
**이벤트 범위**로 등록하세요. **등록 이전 데이터는 소급 적용되지 않습니다.**

`variant` · `session_id` · `product_id` · `position` · `value`

자동 `page_view`는 꺼두고 랜딩에서 수동 발송합니다 — 기본 설정이면 variant가
정해지기 전에 나가서 A/B 분모가 깨집니다.

개발 모드에서는 콘솔에 `[track]`으로 전부 찍힙니다.

## Supabase (선택)

1. supabase.com에서 프로젝트 생성
2. SQL Editor에 `supabase/schema.sql` 실행
3. `.env.example`을 `.env.local`로 복사해 값 입력

> ⚠️ `SUPABASE_SERVICE_ROLE_KEY`에 **`NEXT_PUBLIC_`을 절대 붙이지 마세요.**
> 붙이는 순간 키가 브라우저 번들에 들어가 DB 전체가 공개됩니다.
> RLS는 익명 키에 `insert`만 허용하고, `select`는 정책을 만들지 않아 기본 거부됩니다.

## 알아둘 두 가지

**A/B 배정은 `useEffect` 안에서만 합니다.** 서버 렌더링 중에 `localStorage`를 읽으면
hydration이 깨지면서 배정이 뒤섞여 실험 데이터가 오염됩니다. 확정 전에는
`null` 상태 + 스켈레톤을 보여줍니다.

**한국어 조사를 코드로 처리합니다** (`src/lib/korean.ts`). "네이버**으로**", "카카오**을**"
같은 문장이 대시보드에 뜨면 그 순간 완성도가 무너집니다.
